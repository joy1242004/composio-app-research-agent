    Research workflow

    How an app goes from a name in a spreadsheet to a row in the table below.

    1

    Seed list

    data/apps_seed.csv — 100 apps, their category, and a best-known docs/website URL, taken directly from the assignment brief.

    2

    No-API fetch + keyword extraction

    agent/research_agent.py makes a plain HTTP GET to each URL (no LLM, no Composio key, no search API), strips the HTML with BeautifulSoup, and regex-scans the text against keyword banks for OAuth2, API keys, REST, GraphQL, MCP, free-trial language, and contact-sales/partner-gating language.

    3

    Deterministic scoring

    Confidence (High/Medium/Low) is just a count of independent keyword banks matched. Verdict logic is a fixed decision tree over those same matches — see the code, not a black box.

    4

    Verification pass

    Every record with Low/Medium confidence, an "Unclear" verdict, or a failed fetch is written to data/verification_queue.json for a human to check by hand — this is not optional/cosmetic, see the Verification section.

    Live fetch coverage and verification limits

    The latest full pipeline run processed all 100 seed URLs: 93 returned successfully and 7 failed. The failures were 3 HTTP 404s, 2 HTTP 403s, 1 timeout, and 1 connection error. A successful HTTP fetch only proves that the page was reachable and scanned; it does not mean every extracted field is factually verified.

    In the reconciled final dataset, 91 records are ordinary pipeline-fetched records, 2 are stronger human spot-check records (Attio and Otter AI), and 7 are pipeline-failed records. Failed URLs remain Unclear rather than being guessed.

    The no-API pipeline is an evidence-gathering and triage system. Keyword extraction surfaces likely auth, API, MCP, and access signals, while low-confidence or ambiguous records are routed to human verification.

    Verification: three tiers, reported separately

    The assignment asks for real verification loops and an honest accuracy story. Here it is, without collapsing three different confidence levels into one flattering number.

    Tier 1 — Automated pipeline evidence

    – final records are ordinary pipeline-fetched records. Their fields came from a successful HTTP fetch plus deterministic keyword matching. This is automated evidence, not independent factual verification.

    Tier 2 — Human spot-check

    – apps (Attio, Otter AI) were manually cross-checked against their live docs pages before the no-API pipeline existed. Both spot-checks found the background-knowledge guess was wrong or incomplete — details below.

    Tier 3 — Pipeline failures

    – final records could not be fetched in the latest run. They remain Unclear and require follow-up rather than guessed values.

      Limitations

      • Raw fetch coverage: 93/100. Seven seed URLs failed in the latest full run. In the final reconciled dataset, 91 records remain pipeline-fetched, 2 successful records are represented by stronger human spot-checks, and 7 are pipeline-failed.
      • Successful fetch ≠ verified fact. A reachable page can still be a marketing homepage or omit the exact auth/API details needed for a reliable integration decision.
      • Keyword extraction is not comprehension. Missing keywords do not prove a capability is absent, so ambiguous records are downgraded instead of guessed.
      • One seed page per app. The current pipeline does not crawl full documentation, pricing, developer portals, or linked API-reference pages.
      • Human verification is incomplete. Only 2 apps (Attio and Otter AI) have been manually spot-checked; 83 records remain in the current human verification queue.
      • No live MCP registry cross-check. MCP-related signals should be confirmed against official vendor documentation or a trusted registry during the verification pass.
